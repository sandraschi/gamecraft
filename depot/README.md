# GameCraft Depot - thirteen playable Godot 4 games

Every folder under `games/` is a standalone Godot 4.4 project. Open it in Godot
(or `godot --path games/<slug>`) and press F5. No manual fixups, no missing
resources, no import step.

All twelve are generated by `gamecraft-cli forge` from `gamecraft-commands`
mutations, verified by a deterministic Rust replay, and rendered from that same
trace. Regenerate everything with:

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
cargo run -p gamecraft-cli -- forge --all --out .
```

## First run after cloning

Games that ship generated textures need Godot's import pass once:

```powershell
just godot-import
```

Or open the project in the editor once. Until then, `flight` fails with
`No loader found for resource: res://textures/*.png` (Godot needs the `.import` file).

## What is in each folder

| File | Meaning |
|---|---|
| `project.godot` | Godot 4 project (`run/main_scene` -> `main.tscn`) |
| `main.tscn` | The scene. Deterministic: same bytes on every forge run |
| `scripts/` | `GDScript` shared runtime + per-genre controllers |
| `lint.json` | `scene_lint` output. Ships empty - zero findings is the gate |
| `trace.json` | The verified input script and its measured result |
| `commands.jsonl` | Every scene mutation, one undoable command per line |
| `thumb.png` | Mid-trace frame, 320x180 |
| `play.gif` | The verified trace as an animation |
| `README.md` | Per-game controls, win condition, seed, verification notes |
| `icon.svg` | Project icon |

## The three gates a game must pass

1. **`scene_lint` = 0 findings.** No physics body without a collision shape, no
   signal wired to a missing method, no property referencing an undeclared
   `ExtResource`/`SubResource`, no scene without a current camera.
2. **Trace replay wins inside 600 frames.** The scripted input is re-simulated in
   Rust (`gamecraft-forge::sim`) using the same physics constants the `GDScript`
   exports - so a pass is a claim about the game, not the test harness.
3. **Godot 4.4 headless load is silent.** Every project boots with zero
   `ERROR`/`WARNING` lines. That is what catches things a Rust-side check cannot:
   `%Name` unique-name syntax, unquoted string properties, mismatched script ids.

Byte-identical re-export is also enforced: the forge builds each game twice and
refuses to write a non-identical scene, and 138 files across the depot hash
identically on two separate full runs.

## Honest limits

- The Rust replay is the authority for *reachability*, not a frame-perfect
  physics clone. Real Godot runs the same level and the same constants, but
  `CharacterBody3D` integration differs slightly from the discrete stepper. Win
  states have margin; they are not pixel-perfect speedruns.
- Headless self-play uses hint volumes generated from the verified trace. Human
  play uses the controls in the table. Both reach the same goal.
- The AI opponent in `pong` and the paddle in `breakout` are deterministic
  policies, not learning agents: same inputs, same result, every time.
- "Playable and correct" is the claim. Not "fun". See
  `../docs/GAME_SUCCESS_META.md` for what is actually being optimised here and
  what stays a human decision.
